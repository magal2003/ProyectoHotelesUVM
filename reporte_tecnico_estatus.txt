REPORTE TECNICO DEL ESTATUS ACTUAL DEL PROYECTO

Proyecto: Grand Luxe Hotel / ProyectoHotelesUVM

1. DESCRIPCION GENERAL

El proyecto corresponde a un sistema web de gestion hotelera orientado al manejo de reservas, clientes, empresas corporativas, habitaciones, check-in, check-out y facturacion.

Actualmente el sistema esta dividido en dos partes principales:

- Frontend:
  ProyectoHotelesUVM

- Backend:
  ProyectoHotelesUVMBackend

La base de datos utilizada es MySQL, ejecutandose mediante XAMPP. El backend se conecta a esta base de datos usando las credenciales configuradas en el archivo .env.


2. TECNOLOGIAS EMPLEADAS

Frontend:
- HTML
- CSS
- JavaScript vanilla

Backend:
- Node.js
- Express.js
- MySQL2
- CORS
- dotenv

Base de datos:
- MySQL mediante XAMPP

Gestor de paquetes:
- PNPM

Se esta empleando PNPM en lugar de NPM principalmente por cuestiones de seguridad, eficiencia y mejor control de dependencias. PNPM mantiene una estructura mas estricta, evita dependencias fantasma y reduce duplicacion innecesaria de paquetes.


3. ARQUITECTURA ACTUAL

El sistema funciona bajo una arquitectura cliente-servidor.

El frontend consume la API del backend mediante peticiones HTTP hacia:

http://localhost:3000/api

El backend Express expone endpoints REST y se conecta a MySQL. XAMPP se utiliza para levantar el servicio de MySQL y administrar la base de datos.

La base de datos principal es:

hotel_reservations

6. ESTATUS ACTUAL

El proyecto ya no es solamente una maqueta frontend. Actualmente cuenta con backend funcional, conexion a MySQL y varias acciones conectadas directamente a la base de datos.

El frontend ya consume datos reales desde el backend para dashboard, empresas, reservas, checkout y administracion. Ademas, varios botones que antes eran solo visuales ya ejecutan operaciones reales.

Tambien se agrego una bitacora de actividad reciente en el frontend. Esta bitacora muestra eventos operativos del sistema, como nuevas reservas, altas de habitaciones, cambios de estado, check-in, check-out, liquidacion de cuentas y generacion de facturas. La informacion se almacena localmente en el navegador mediante localStorage, por lo que se conserva aun si se recarga la pagina.

Se actualizo el flujo de autenticacion. El inicio de sesion ahora solo solicita correo y contrasena; el rol del usuario se determina desde la base de datos. La seleccion de rol se movio al proceso de creacion de cuenta, donde se capturan los datos necesarios del usuario.

Se corrigio la logica de asignacion de habitaciones. Antes una habitacion podia repetirse en reservas con fechas traslapadas. Ahora el backend valida disponibilidad por rango de fechas, tipo de habitacion, estado de la reserva y requisito de no fumadores. Ademas, el frontend permite seleccionar el tipo de habitacion y la habitacion especifica disponible. Si no existe disponibilidad para el tipo seleccionado y las fechas indicadas, el sistema muestra un error y no permite crear la reserva.

Tambien se limito la creacion de habitaciones a tipos controlados: Estandar y Suite. Aunque la base de datos actualmente guarda el tipo como texto y no existe una tabla separada de tipos, el frontend muestra un selector y el backend valida los valores permitidos.

El proyecto se encuentra en una etapa funcional inicial, adecuada para pruebas locales y presentacion academica. Sin embargo, todavia requiere mejoras para considerarse una version completa o lista para produccion.

El estado actual es funcional para pruebas locales y demostracion, aunque todavia requiere completar modulos administrativos, seguridad de autenticacion y mejoras de interfaz para alcanzar un nivel mas robusto.
